# Phira 本地谱面管理系统：公开架构说明

本文档介绍项目对外公开的整体架构、数据边界和部署责任，不包含内部协议、凭据处理、调试流程或机器相关配置。

> [!IMPORTANT]
> 本项目是面向 Phira 客户端的社区项目，并非 Phira 官方项目，与 Phira 官方不存在隶属、授权或背书关系。

## 设计目标

- 在不修改官方数据的前提下提供本地谱面
- 隔离不同成员和服务实例的数据与管理权限
- 保存独立的本地成绩、排行榜和谱面评分
- 通过独立的多人服务支持房间与本地选谱
- 默认减少敏感请求内容的记录
- 允许部署者按自己的网络环境配置 HTTPS 和访问控制

## 总体架构

~~~text
Phira 客户端
    |
    +-- HTTPS --> Gateway
    |                 |
    |                 +-- 本地谱面、资源与成绩
    |                 |
    |                 +-- 其他兼容请求的上游服务
    |
    +-- TCP ----> 多人房间服务
~~~

Gateway 负责识别本地谱面请求、返回相应资源，并在允许时把本地谱面加入列表和搜索结果。多人房间由独立组件维护，避免将实时房间状态与 HTTP 谱面服务混在同一状态机中。

## 谱面与服务实例

谱面包、媒体资源、元数据和本地成绩按服务实例隔离。每个实例具有独立的所有者、协作范围、启用状态和列表可见范围。

新上传谱面的 ID 在当前服务中必须能够唯一定位。服务端负责检查冲突，避免谱面详情、资源和成绩被错误地归入其他实例。

上传的原始内容由部署者和上传者负责。兼容处理应使用派生文件，不应无提示地覆盖上传者提供的原始谱面包。

## 列表与搜索

启用本地列表功能后，Gateway 会把符合条件且已上架的本地谱面合并到客户端列表和搜索结果中。

实例可以设置为所有人可见、指定用户可见或不加入列表。筛选失败或无法可靠理解请求条件时，服务应保持原响应，避免错误注入本地内容。

> [!WARNING]
> 列表可见范围不是资源下载权限。知道详情或资源链接的人仍可能直接访问内容；严格私有分发需要在详情和资源接口上另外实施经过验证的授权。

## 本地成绩

本地谱面的成绩、排行榜和评分保存在当前部署中，不计入官方经验、RKS 或官方排行榜，也不应冒充官方成绩。

只有在服务端能够验证所需数据时，才应保存或展示成绩。无法验证的数据不得被猜测、伪造或提交到外部服务。

## 多人房间

多人房间由 PMP+ 组件提供，负责房间成员、选谱、准备、同步开始和结果广播。

使用本地谱面时，参与者需要能够访问同一个谱面服务。网页管理账号、游戏用户身份和房间所有者属于不同的权限边界，不应相互替代。

## 安全与隐私边界

- 管理凭据、数据库口令、Cookie、会话信息和私钥不得进入公开仓库。
- 普通日志不应记录认证信息、完整请求体或不必要的用户资料。
- 管理权限、实例归属和高风险操作必须由服务端校验。
- 公网入口应使用有效的 HTTPS，并限制内部维护端口的访问范围。
- 注册审核收集的社交账号和申请资料应按单独发布的隐私政策处理。
- 普通 API 转发不代表官方身份验证、官方授权或官方成绩验证。

## 部署责任

公开部署前，部署者需要自行准备并维护：

1. 获得合法授权的谱面、音乐和曲绘资源
2. HTTPS 证书以及安全保存的私钥
3. 正确的上游服务和公网入口配置
4. 防火墙、反向代理和访问控制规则
5. 账号、谱面、成绩与数据库备份
6. 面向用户的隐私政策和内容处理规则

配置文件中的示例地址和凭据只用于说明，不能直接作为生产配置。疑似泄露的凭据必须立即轮换，删除文件或修改文档不能使已经泄露的凭据恢复安全。
